TP : Développement d'un outil de diagnostic réseau

Environnement au choix : Python ou PowerShell

Contexte

Dans le cadre de l'unité d'enseignement Collège André-Grasset, les étudiants doivent réaliser un travail pratique portant sur l'automatisation des tâches d'administration et de diagnostic réseau. L'objectif est de concevoir une application en ligne de commande (CLI) capable d'exécuter plusieurs tests de connectivité et de résolution.

Objectifs pédagogiques

  • Maîtriser les bibliothèques ou cmdlets liés aux réseaux.
  • Savoir exécuter et parser les résultats de commandes système.
  • Gérer les entrées utilisateur et la validation des données.
  • Structurer un projet en modules / fonctions réutilisables.
  • Produire une documentation technique et un guide d'utilisation.

Travail demandé

L'étudiant doit développer une application permettant à un utilisateur de choisir et d'exécuter les tâches de diagnostic suivantes :

  1. Ping : envoyer des requêtes ICMP vers une adresse IP ou un nom de domaine et afficher le temps de réponse.
  2. Résolution DNS : résoudre un nom de domaine en adresse IP (et inversement, si possible).
  3. Traceroute : afficher le chemin suivi par les paquets vers une destination.
  4. Test de port (TCP) : vérifier si un port spécifique est ouvert sur une machine distante.
  5. Informations réseau locales : afficher la configuration IP de la machine (adresse IP, passerelle, DNS).

Environnement de travail

L'étudiant doit choisir un seul des deux environnements suivants :

Option A — Python

  • Modules subprocess, socket, os, argparse (ou typer / click).
  • Gestion des erreurs et des timeouts.
  • Sortie colorée ou formatée dans le terminal.

Option B — PowerShell

  • Cmdlets Test-Connection, Resolve-DnsName, Test-NetConnection, Get-NetIPConfiguration.
  • Structuration en fonctions et paramètres avancés.
  • Gestion des erreurs avec try/catch.

Contraintes techniques

  • L'application doit être exécutable en ligne de commande.
  • Un menu interactif ou des arguments CLI doivent permettre de choisir la tâche.
  • Le code doit être commenté et respecter les bonnes pratiques de nommage.
  • Un fichier README.md expliquant l'installation et l'utilisation est requis.

Livrables

  1. Le code source complet (dépôt Git ou archive ZIP).
  2. Un rapport technique (PDF) de 5 à 10 pages décrivant l'architecture, les choix techniques et les difficultés rencontrées.
  3. Une démonstration vidéo (5 min max) ou une session de démonstration en présentiel.
